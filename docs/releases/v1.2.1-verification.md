# Core v1.2.1 pre-tag verification

Verified on 2026-11-08. This record accompanies the
[release notes](v1.2.1.md); it does not publish or approve a tag automatically.

## Source and release scope

The tested implementation is merged main
`949cd9b13a68f3c62494af0055b38aead84834f1` (PR #24), following the encoding
optimization in PR #22 and selective materialization/JSONata correction in
PR #23. Compared with core v1.2.0, root `go.mod` and `go.sum` are unchanged.
This release-preparation change adds documentation and consumer verification
fixtures only. No Go runtime source, public API, dependency or guest changes
are included in release preparation.

Bertram tested an isolated `git archive` of that commit. The transferred
`tar.gz` SHA-256 was
`9cb579375b641a19aec78b782add68009a6f5786648000aacb2c98641dcf63cd`.
macOS tested the same implementation in the release branch. Local verification
used `GOEXPERIMENT=''`; experimental jsontext decoding was not enabled.

The final tag should target the reviewed, merged release-preparation commit
after its required hosted checks pass. Its runtime source must still match the
verified implementation; further runtime changes require fresh relevant checks.
Public retrieval of the eventual `v1.2.1` tag is a post-publication check.

## Security and hosted platform coverage

Fresh `govulncheck` v1.9.0 gates passed using Go 1.26.10 for `linux/amd64`,
`windows/amd64` and `darwin/arm64`. Each gate analyzed all three runtime/assessment
modules with tests and a CGO-free public JavaScript example binary, checked
module/root coverage and parsed findings rather than trusting JSON-mode exit
zero alone. All reported no findings. The security-gate Python tests also passed.
These are source/binary cross-target scans, not local Windows execution or a
new audit of the embedded C engine.

The verified merged baseline additionally passed its complete
[hosted CI run](https://github.com/mellowforge/jsontrans-go/actions/runs/42499164478)
and [Go security run](https://github.com/mellowforge/jsontrans-go/actions/runs/42499164463).
That CI run includes native macOS/Linux matrices, native Windows JavaScript
tests/race/vet, strict owned assessment probes, adapter fuzz/soak checks,
module packaging and the pinned guest rebuild/byte comparison. Those hosted
results belong to the baseline commit, not a future release-preparation merge.
The JavaScript runtime and guest are unchanged; their
[production approval](../javascript-production-readiness.md) remains in effect.

See the [local verification guide](../local-verification.md) for integration,
security scan and platform commands.

## Public module consumption before tagging

Clean temporary native and JavaScript applications fetched the verified commit
through `proxy.golang.org` as
`v1.2.1-0.20261108161751-949cd9b13a68`, with a new module cache,
`GOSUMDB=sum.golang.org`, `GOWORK=off`, no replacements or private-module
exceptions, and `CGO_ENABLED=0`. Both applications built and ran with Go 1.26.10
and Go 1.27.3. The JavaScript application explicitly selected released v1.0.1.

The fixtures verify native and mixed batch results, missing/null, output byte
ownership, existing APIs, the computed-key correction, a selective object
constructor, exact large JSONPath numbers, JavaScript prepared fallback and
bindings, unsupported-limit diagnostics, and engine closure. Dependency checks
ensure native consumers do not import JavaScript, JavaScript-only consumers do
not import the native language engines, and neither imports experiment/NATS/
Testcontainers code. `go mod verify` passed for both consumers.

Reproduce using absolute paths to the two toolchains and a new output directory:

```sh
python3 docs/releases/v1.2.1-checks/consume.py \
  --go126 /absolute/path/to/go1.26.10/bin/go \
  --go127 /absolute/path/to/go1.27.3/bin/go \
  --output /tmp/jsontrans-v121-consumers
```

This deliberately verifies an already retrievable commit. It does not pretend
that an unpublished stable tag exists or substitute a local synthetic module zip
for the public download check.
