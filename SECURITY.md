# Execution safety and vulnerability reports

Expressions may be supplied by untrusted users. Compilation, input conversion,
evaluation, and output conversion use cooperative work and size budgets.
Defaults are a 1-second timeout, 64 KiB expressions, depth 256, one million
steps, 100,000 items per collection, 16 MiB input/output, and a 50 ms regex
timeout. Configure larger positive limits for trusted workloads.

The regex timeout bounds each JSONata match inside the matcher. JSONPath uses
Go's linear-time RE2 engine and checks the regex timeout after each match.

Configured limits are defaults. `EvalOptions.Limits` can raise or lower them for
one evaluation, so applications must not pass untrusted limit overrides.

These controls are not OS memory isolation or guaranteed immediate termination.
Some library operations can only check cancellation before and after a call.
Applications requiring hard isolation should run the library in supervised
processes with appropriate operating-system resource limits.

Registered Go functions are trusted application code. They must cooperate with
context cancellation, account for their own allocations, and be concurrent-safe.
Expression input alone does not grant filesystem or network access; do not
register functions exposing capabilities that expression authors should not have.

The optional JavaScript module has a different execution profile from the native
engines. Its guest is capability-free (no host imports or WASI instance), and
only package-generated bytecode is accepted by the internal execution boundary.
Source expressions remain untrusted. Wall-clock interruption and guest linear
memory caps apply to each call; explicit instruction, separate regex and stack
quotas are unsupported. Host conversion is cooperative. A guest cap does not
bound host allocations, concurrent calls, executable-code caches or process RSS.
Applications must bound admission/concurrency and control limit overrides.

Each JavaScript evaluation uses detached values and a fresh guest. Applications
own the engine and must Close it; Close cancels and drains admitted calls before
releasing runtime/cache resources. Closure has no hard deadline or immediate RSS
reclamation guarantee. Diagnostic text is bounded but may contain secrets,
control characters and user-forged names/stacks; treat it as untrusted data when
logging or rendering. There is no diagnostic redaction guarantee.

Embedded QuickJS/WASI components are not covered by a Go dependency scanner.
Updates require review of upstream security notices, source/toolchain pins,
licenses and the reproduced artifact, followed by capability/integrity gates,
all owned probes, race/fuzz/stress tests and platform checks. Do not replace the
guest with an unverified binary. See the [JavaScript hardening record](docs/javascript-hardening.md)
and [execution contract](docs/javascript-execution-contract.md).

Do not disclose exploitable vulnerabilities in public issues. Before public
release, maintainers must enable private vulnerability reporting on the GitHub
repository and identify a monitored contact route there. Releases currently
reside in a private repository. The optional JavaScript module remains a preview;
it has not been released as a supported processor.
