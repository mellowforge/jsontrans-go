# jsontrans-go v1.2.1

Module: `github.com/mellowforge/jsontrans-go`; package: `jsontrans`.
This core patch release reduces the cost of prepared JSON results and corrects
a JSONata object-constructor edge case. Go **1.26 or newer** remains required.
Public APIs, dependencies and default execution limits are unchanged.

## Install

After the `v1.2.1` tag is published:

```sh
go get github.com/mellowforge/jsontrans-go@v1.2.1
```

Release preparation does not publish a tag. The
[verification record](v1.2.1-verification.md) identifies the merged implementation
and checks completed before tagging.

## Less copying and selective field access

- Prepared byte-result helpers reuse the encoded size established during result
  validation. Encoding no longer clones containers, normalizes strings or
  measures scalar encodings a second time.
- JSONPath singular selectors materialize only the selected container subtree.
- Eligible JSONata root object constructors read scalar fields directly from
  the prepared document. Supported expressions include unique literal keys,
  conservative scalar operations and numeric `+`, `-` and `*` expressions.
  Unsupported expressions or input shapes use the full native evaluator.

These improvements apply to `EvalPreparedJSON` and `Batch.EvalPreparedJSON`;
selective materialization also benefits eligible prepared Go-value results.
Existing direct evaluation, registry and external-adapter APIs remain available.
Whole-input validation, numeric behavior, input preservation, detached outputs,
cancellation, output byte caps and batch error attribution remain effective.
Removing redundant work can change the exact step limit at which a call stops.
This remains an allocating implementation with cooperative in-process controls.

## JSONata compatibility correction

A computed object key that evaluates to missing now omits its entry without
evaluating the entry's value, matching JSONata 2.2.2. For example,
`{missing:$error("must not run"),"present":null}` over `{}` returns
`{"present":null}`. Previously it incorrectly raised `T1003`. Null and other
non-string keys still report their native type error.

JSONPath RFC 9535/RFC 9485 and JSONata 2.2.2 remain the compatibility targets.
See the [compatibility policy](../compatibility.md) for fallback boundaries,
Go-boundary behavior and the two documented JSONPath fixture errata.

## Measured workloads

Native measurements on Bertram (Ubuntu 24.04, Intel Core i9-13900K, Go 1.27.3,
one runtime slot) include per-message preparation, evaluation and JSON encoding.
Rules are precompiled. For the selective-materialization experiment's target
1-KiB object fixtures, median results across five paired rounds were:

| Processor | Rules per message | Before → after, µs/message | Allocations before → after |
| --- | ---: | ---: | ---: |
| JSONata | 1 | 35.43 → 17.54 | 448 → 70 |
| JSONPath | 1 | 28.50 → 16.88 | 395 → 72 |
| JSONata | 16 | 330.70 → 46.55 | 6,508 → 414 |
| JSONPath | 16 | 216.08 → 44.76 | 5,613 → 446 |

These compare the selective change against the preceding encoding optimization,
not the combined release against v1.2.0. Scalar fan-out improved separately in
the [encoding experiment](../benchmarks/prepared-encoding-linux-2026-11-08/README.md).
The [selective-materialization report](../benchmarks/selective-materialization-linux-2026-11-08/README.md)
includes full samples, Go 1.26.10 controls and reproduction commands. These
fixture-specific results do not establish a general throughput or latency guarantee.

The [matched NATS experiment](../benchmarks/nats-optimization-linux-2026-11-08/README.md)
recorded all 324 prepared/batch cases on optimized main as lossless, up from
314/324 on the pre-optimization baseline, with no transformation, transport or
output-validation errors. The
[longer focused trials](../benchmarks/nats-focused-linux-2026-11-08/README.md)
also retained a configuration-sensitive tail-latency regression: four separate
prepared object transformations with one worker and `GOMAXPROCS=1` increased
median per-run end-to-end p99 from 3.18 to 3.92 ms across six pairs, despite
lower processing time and allocation traffic. The four-rule batch p99 was
mixed and near baseline. Batch evaluation remains the intended fan-out API;
measure your own routing, concurrency and runtime configuration. The library
does not change process-wide scheduler settings.

## Optional JavaScript module

`github.com/mellowforge/jsontrans-go/javascript@v1.0.1` remains independently
versioned and compatible with this core patch. Its minimum core stays v1.2.0;
no JavaScript release or dependency bump is required to select core v1.2.1.
After core publication, applications using both modules can run:

```sh
go get github.com/mellowforge/jsontrans-go@v1.2.1 \
  github.com/mellowforge/jsontrans-go/javascript@v1.0.1
```

The guest, runtime dependencies and supported execution profile are unchanged.
The root module acquires no JavaScript, NATS or Testcontainers dependency.
This release does not enable experimental jsontext decoding, change the Go
minimum, add streaming, pool runtimes or introduce a new public API.
