# jsontrans-go v1.2.0

Module: `github.com/mellowforge/jsontrans-go`; package: `jsontrans`.
Go **1.26 or newer** is required. This is an additive core release following
v1.1.0. The optional JavaScript module remains separately versioned.

## Install

After the `v1.2.0` tag is published:

```sh
go get github.com/mellowforge/jsontrans-go@v1.2.0
```

Before tag publication, the merged implementation is available at the verified
PR #19 commit:

```sh
go get github.com/mellowforge/jsontrans-go@650b139440d4afb6ef7822bccd311b296d9c2d7b
```

Go resolves that commit to
`v1.1.1-0.20261107064307-650b139440d4`; no local `replace`, workspace or
`GOPRIVATE` configuration is required. The stable release uses the merged
release-preparation commit; its runtime code matches this verified implementation.

## Prepared documents can return JSON bytes directly

Two new root APIs combine prepared evaluation with bounded JSON encoding:

```go
result, err := jsontrans.EvalPreparedJSON(ctx, program, document, options)
results, err := batch.EvalPreparedJSON(ctx, document, destination, options)
```

Compile predefined rules once, prepare each incoming message once, and select
one program or an ordered batch. Both helpers return `JSONResult` values:

- Defined results own their encoded bytes. Missing has `Defined == false` and
  nil bytes; defined null contains the bytes `null`.
- Batch calls reuse destination slice capacity without overwriting previously
  returned byte buffers. Separate concurrent calls need separate destinations.
- Evaluation and encoding share each expression's deadline. Batch output limits
  also bound the sum of actual encoded result lengths, including escaping.
- Failures preserve native diagnostics and cancellation. A failed batch returns
  no partial results; `BatchError.Index` identifies the failing expression.

JSONPath keeps its match-list shape and selected numeric spelling. JSONata keeps
native shapes and binary64 numeric behavior. Existing `Eval`, `EvalJSON`,
`EvalPrepared`, `Batch.EvalPrepared`, and transformer entry points remain available.
No required methods were added to `Processor` or `Program`.

See the [API contract](../prepared-json-results.md),
[runnable example](../../examples/prepared-json/main.go), and
[use-case diagrams](../use-cases.md).

## Adapter limits and dependency update

- Add optional `EvalLimitSupport` and `LimitSet` declarations. Registry, JSON,
  prepared and batch helpers reject explicit unsupported limit overrides before
  adapter evaluation and omit unsupported fields from synthesized options.
  Adapters without the interface retain existing forwarding behavior.
- Fix prepared external dispatch to retain both registry and program configured
  limits. Forwarded option copies cannot mutate shared settings or raise common
  conversion budgets. See [limit forwarding](../registry-limit-forwarding.md).
- Update `golang.org/x/text` from v0.36.0 to v0.43.0, incorporating the
  [recorded Go dependency remediation](../javascript-go-security-updates.md).

Default execution limits and native language compatibility targets are unchanged.
The root module acquires no JavaScript, NATS or Testcontainers dependency.

## Optional JavaScript compatibility

The existing `github.com/mellowforge/jsontrans-go/javascript@v1.0.0` module works
with the new core helpers through detached prepared-document fallback. After
core publication, applications can select both versions explicitly:

```sh
go get github.com/mellowforge/jsontrans-go@v1.2.0 \
  github.com/mellowforge/jsontrans-go/javascript@v1.0.0
```

This core release changes no guest, engine dependency, capability or execution
guarantee of that adapter. Fresh guest state and its
[supported execution profile](../javascript-execution-contract.md) remain intact.
Its existing minimum-core pseudo-version remains valid; selecting core v1.2.0
does not require a JavaScript patch release.

## Verification and measured workloads

PR #19 passed the full hosted CI matrix, including pinned conformance, reference
comparisons, fuzzing, native platform checks, Go security scans and guest
reproducibility. The [final NATS validation](../benchmarks/message-nats-public-api-2026-11-07/README.md)
also records 30 local verification steps on Bertram and 486 valid load cases.
All 162 single-rule cases and all 108 eight-worker prepared/batch cases were
lossless. Fifty overloaded cases explicitly recorded application-queue rejection;
these brief measurements do not establish production capacity.

Release preparation additionally verifies clean outside consumers of the merged
implementation through public Go module downloads and checksum verification,
with `GOWORK=off`, no replacements, and CGO disabled. Native JSONPath/JSONata,
mixed batch, missing/null, byte ownership, existing APIs, and released JavaScript
integration are exercised on Go 1.26.10 and Go 1.27.3. Native consumers do not
import the optional runtime; JavaScript-only consumers do not import the native
language engines.

The [Go 1.27/jsontext assessment](../assessments/go127-json.md) remains an opt-in
experiment. This release does not switch the default decoder, raise the Go
minimum, add a streaming API, or introduce runtime pooling. Prepared encoding
still allocates and retains the documented cooperative in-process controls.
